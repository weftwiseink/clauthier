# Software Factory Landscape: Developments Since Late 2025

> BLUF: The last ~6-12 months shipped two platform-native features that directly overlap cdocs mechanisms: Claude Code's dynamic-workflow `Workflow` tool (scripted, near-zero-token multi-agent orchestration) competes with `iterate`/`oversee`'s hand-rolled, token-paying overseer loop, and Anthropic's multi-agent `Code Review` productizes the fresh-reviewer-per-round pattern cdocs already runs for documents.
> Spec-driven tools (AWS Kiro, GitHub Spec Kit) converged on the same spec→plan→tasks→implement shape as `propose`→`implement`, confirming the shape rather than offering a new idea to adopt.
> Durable-memory work (Claude Auto Memory, Anthropic's "Dreaming" consolidation, Letta's move to git-backed memory files) validates cdocs' bet on git-committed markdown as the memory substrate, and nothing seen subsumes the devlog/triage pattern.
> Net recommendation: watch the `Workflow` tool closely as a candidate to mechanize the bookkeeping half of `iterate`/`oversee` (the documented token-spend pain point) while keeping judgment calls in prose; no other finding argues for new cdocs mechanism today.
> Two vendors' own published guidance double as external validation of cdocs' existing rules: Cognition's "Multi-Agents: What's Actually Working" independently arrives at single-writer-per-file plus fresh-context review, and Anthropic's own "when to use multi-agent systems" post names the exact failure mode (`judge` exists to guard against) a lone verification subagent declaring premature success.

## Landscape

### Vendor coding agents: background/cloud sessions are now table stakes

Every major vendor shipped an async, laptop-closeable execution mode in this window:

- **Anthropic Claude Code**: Cloud Sessions moved out of research preview to GA on September 23, 2026, running on Anthropic-hosted VMs, reachable from `claude.ai/code`, the mobile app, or `claude --cloud` ([Anthropic launches cloud sessions](https://alphasignal.ai/news/anthropic-ships-claude-code-cloud-sessions-so-developers-can-code-without-a-laptop)). "Projects" layers parallel threads on top, each thread a full cloud session on its own branch and repo copy ([MarkTechPost, 2026-09-17](https://www.marktechpost.com/2026/09/17/anthropic-launches-claude-code-projects-in-beta-parallel-cloud-sessions-that-keep-running-after-you-close-your-laptop/)).
- **OpenAI Codex**: cloud environments (prepare a workspace once, dispatch tasks from any device) landed at DevDay, September 29, 2026 ([OpenAI, "Introducing the Codex app"](https://openai.com/index/introducing-the-codex-app/)); parallel cloud sandboxes queue 3-5 tasks concurrently with separate git state.
- **GitHub Copilot**: the async Coding Agent (GA across VS Code/JetBrains, March 2026) turns an assigned issue into a PR via GitHub Actions; see "Agent-to-agent review" below for its most cdocs-relevant feature, `.github/agents/`.
- **Google Jules**: shifted from reactive to proactive in 2026 - MCP server support (Feb 2, 2026), a "CI Fixer" beta that auto-repairs failing checks on its own PRs, and a Render integration that inspects failed deploys unprompted ([testingcatalog.com](https://www.testingcatalog.com/google-prepares-jules-to-become-always-on-ai-swe-agent/)). A ground-up "Jules V2" (goal-directed, not task-directed) is in early access.
- **Cursor 2.0** (Oct 29, 2025): a purpose-built "Composer" model plus a multi-agent interface running up to 8 parallel agents in separate worktrees/remote machines; Background Agents renamed Cloud Agents ([cursor.com/changelog/2-0](https://cursor.com/changelog/2-0)).
- **Devin (Cognition)**: "Devin can now Manage Devins" (March 19, 2026) and "...Schedule Devins" (March 20, 2026) add a coordinator that decomposes a task across isolated managed-Devin VMs and self-scheduling recurring runs; "Devin Fusion" (June 29, 2026, expanded to Desktop/CLI Sept 11, 2026) pairs a frontier planner with cheaper executor agents for ~60% lower cost at near-frontier quality.
- **OpenCode** (opencode.ai): a typed plugin system distinct from skills - plugins hook runtime events (`tool.execute.before/after`, `session`) in TypeScript, where skills teach the agent what to do. More granular than Claude Code's shell-script hook surface; a growing third-party ecosystem (persistent-memory, sandboxing plugins) is organically building pieces cdocs' own rules address by convention.
- **Factory.ai** is the one vendor using the report's own term as a first-party label: "Factory 2.0: From coding agents to software factories" ([factory.com/news/software-factory](https://factory.com/news/software-factory), June 15, 2026) frames a factory as a closed loop - signals (bugs, feedback, requirements) → triage → plan → build → test → review → security → ship → monitor → back to signals - with model-agnostic routing and continual learning across every SDLC stage. Its **Droid Computers** ([factory.com/news/droid-computers](https://factory.com/news/droid-computers)) persist filesystem/credentials/process memory across sessions, explicitly pitched against "the ephemeral sandboxes used by other cloud agents." Private preview; funding/scale figures are secondary-sourced only.
- **Sourcegraph's Amp** (spun out independently Dec 2025) frames itself around *specialized subagents*: a main thread can reportedly invoke `Oracle` (a second-opinion model), `Librarian` (cross-repo research), and `Painter` (image generation) autonomously - **flag: this architecture is secondary-sourced only**, not confirmed against ampcode.com directly in this pass.

### Orchestration frameworks on Claude Code itself

Three Claude Code features shipped in this window that are squarely "agent orchestration framework," not vendor-landscape noise:

- **Dynamic Workflows / the `Workflow` tool** (shipped v2.1.154, May 28, 2026; primary source [code.claude.com/docs/en/workflows](https://code.claude.com/docs/en/workflows)): a workflow is a JavaScript file that orchestrates subagents via `agent()`, `parallel()`, `pipeline()`, and `phase()`. The script itself runs free; token cost is only the `agent()` calls. `pipeline()` runs each item through every stage independently (no cross-item barrier); `parallel()` barriers and nulls a throwing thunk rather than rejecting. Ceilings: 16 concurrent agents, 1,000 per run, 4,096 items per `parallel()`/`pipeline()` call. `agent()` accepts a JSON-Schema `opts.schema` to force structured output with auto-retry on shape mismatch.
- **Claude Mods** (v2.1.287/288, October 1-2, 2026): plugins can now hook deeper runtime events (`agent.spawn`, `tool.call`, `prompt.submit`, `turn.step`, `config.set`, `ui.render`, …) in TypeScript rather than the older shell-script hook surface. A built-in mod, "You should know," runs a side-agent that watches the main session and flags things the user or Claude might miss.
- **Agent teams / "teammates"** (Sept-Oct 2026 changelog entries): a named, resumable, idle/waiting-stateful agent concept distinct from a one-shot subagent dispatch, plus `/advisor` pairing (e.g., Sonnet 5.5 can advise Opus 4.7/4.8) for a second-model opinion mid-turn.
- **Anthropic's own orchestration guidance**, "When to use multi-agent systems (and when not to)" ([claude.com blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them), Jan 23, 2026): start single-agent (multi-agent costs 3-10x the tokens); the three justified cases are context protection, parallelization, and specialization; decompose by *context*, not by SDLC phase (sequential plan→build→test shares too much context, poor handoffs); a low-context verification subagent catches issues reliably but is prone to an "early victory problem" (declaring success prematurely) absent an explicit, checkable completion criterion.

### Agent-to-agent review

- **Anthropic Code Review** (announced March 9, 2026, [claude.com/blog/code-review](https://claude.com/blog/code-review)): dispatches a team of specialized agents per PR (logic errors, boundary conditions, API misuse, auth flaws, project conventions), with an aggregator agent ranking findings by severity. Internal numbers: substantive-comment rate rose from 16% to 54%; engineers marked <1% of findings incorrect. Research preview for Team/Enterprise, $15-25 and ~20 minutes per review.
- Point-solution review products converged on multi-agent architectures in 2026: **CodeRabbit** (most-installed GitHub Marketplace code-review app, >200K installs) moved past linear static-analysis pipelines; **Greptile v3** rebuilt on the Claude Agent SDK for multi-hop investigation (follows call chains and git history before surfacing an issue); **Qodo (CodiumAI)** split into separate bug/quality/security/test-coverage agents. An arXiv paper, "Is Agentic Code Review Helpful? Mining Developers' Feedback to CodeRabbit Reviews in the Wild" ([2607.03316](https://arxiv.org/pdf/2607.03316)), is a direct empirical study of this pattern in production; not independently re-verified beyond its abstract here.
- Cognition's **"Multi-Agents: What's Actually Working"** ([cognition.com/blog/multi-agents-working](https://cognition.com/blog/multi-agents-working), April 22, 2026) is the most load-bearing primary source found for cdocs' own discipline: writes should stay single-threaded on one primary agent while other agents contribute *intelligence, not actions*, since actions "carry implicit decisions that might conflict" - the exact justification behind "one writer per file." Patterns it reports working: a fresh-context review agent (~2 bugs/PR caught, 58% severe), a "smart-friend" frontier model assisting a weaker primary, and manager-child delegation.
- **GitHub Copilot coding agent** ([github.blog, Feb 26, 2026](https://github.blog/ai-and-ml/github-copilot/whats-new-with-github-copilot-coding-agent/)) now runs a self-review pass on its own diff before opening a PR, and ships **`.github/agents/`**: a checked-in config directory where a team codifies repo-specific agent process (e.g., a benchmarking step required for perf-optimization tasks) - the most direct vendor analog to a process plugin like cdocs, shipped natively, no install required.
- **OpenAI Codex's Agents API** (public beta, DevDay, Sept 29-30, 2026) generalizes "Codex's multi-agent capabilities" (hosted execution, persistent memory, tool search, context compaction) into a platform primitive any app can call, alongside a revamped CLI `/agents` view for monitoring several concurrent delegated tasks.

### Spec-driven development

- **AWS Kiro**: reached GA May 7, 2026 as the official successor to Amazon Q Developer (which sunsets April 30, 2027). Workflow: requirements spec → design doc → agent implements and tests against them. Pricing is credit-based, $0-$200/user/month across five tiers; a "full spec-driven feature build" runs ~15-25 credits. "Kiro Web" reached GA September 1, 2026; "Kiro workflows" (multi-agent, less-supervised task completion) appear in AWS's October 5, 2026 weekly roundup.
- **GitHub Spec Kit**: MIT-licensed, open source (`github/spec-kit`), shipped v1.0.0 August 21, 2026, now at v1.0.13 (Sept 29, 2026) with 139K+ GitHub stars. Workflow: Specify (what/why) → Plan (how: architecture, libraries, data model) → Tasks (agent decomposes into reviewable units) → Implement (agent executes against the spec). A June 2026 `/speckit.converge` command explicitly closes the loop between a spec and the code that implements it. Microsoft's Developer Blog gave it first-party coverage the same month.

### Durable memory / state for agents

- **Claude Auto Memory**: a per-project `memory/` directory (visible in this very session's own `MEMORY.md`) where the first ~200 lines of a primary file auto-load every conversation and topic-specific files load on demand.
- **Anthropic "Dreaming"** (research preview, May 6, 2026, Managed Agents API): a scheduled consolidation pass that reads a memory store plus up to 100 prior sessions and writes back a reorganized store (merged duplicates, stale entries replaced), triggered after 5 accumulated conversations or 24 hours.
- **Letta (formerly MemGPT)**: rearchitected its agent loop "incorporating lessons from ReAct and Claude Code" in 2026, and on March 16, 2026 began sunsetting server-side memory tools/templates/identities/MCP integrations in favor of **git-backed memory files** and client-side orchestration - a notable convergence toward exactly the git-committed-markdown substrate cdocs already uses.

### Evaluation of agentic dev workflows

- **SWE-bench Pro** ([arxiv 2609.08149](https://arxiv.org/pdf/2609.08149)): 1,865 problems across 41 actively-maintained repos, aimed at longer-horizon, enterprise-like tasks; a 2026 OpenAI audit flagged ~30% of its tests as broken or overly strict - a concrete, citable caution about benchmark trust.
- **Terminal-Bench**: 2.1 saturated (9 models at 87-92%); the community moved to 4.0, where the current leader sits at 58.2%, re-opening headroom.
- **METR time-horizon**: the 50%-reliability autonomous-task-length metric's doubling period compressed from ~7 months (2019-2024) to ~105 days per METR's own fit ([metr.org, Feb 2026](https://metr.org/blog/2026-1-29-time-horizon-1-1/)); a single, unverified social-media data point puts "Claude Mythos Preview" at a 16-hour horizon.
- **"The Scaffold Effect in Coding Agents"** ([arxiv 2607.22585](https://arxiv.org/pdf/2607.22585)) argues harness/scaffold choice is itself a hidden variable in coding-agent evaluation - i.e., the orchestration layer around a model materially changes measured capability, not just the model.
- **"Position: Coding Benchmarks Are Misaligned with Agentic Software Engineering"** ([arxiv 2606.17799](https://arxiv.org/pdf/2606.17799)) is a direct critique of single-patch benchmarks as proxies for multi-step, multi-agent SWE work.

## Relevance to cdocs

| Idea | Touches | Take | Why |
|---|---|---|---|
| **Workflow tool** (scripted `agent`/`parallel`/`pipeline`) | `iterate`, `oversee`, `full-send`, `orchestration-discipline.md` | **Watch, borrow idea** | The one platform feature that could genuinely let cdocs delete something: the overseer currently *is* the orchestrator, paying full context on every dispatch/judge/re-dispatch turn - the cost `cdocs/reports/2026-09-20-token-spend-by-role.md` measured (a warm implementer hit 966K tokens). A near-zero-token script could own the mechanical fan-out (dispatch implementer, dispatch fresh reviewer, loop until N reviews, hand to judge) while the devlog stays the script's audit trail. Not a drop-in: the maintainer's "trust agent intuition over formalism" preference argues against a fully deterministic pipeline, since the valuable part of `iterate` is the judge's qualitative call, not the bookkeeping. Adopt only the bookkeeping half; keep judgment in prose.
| **Claude Mods** (deeper plugin hooks, incl. `agent.spawn`) | `plugins/cdocs/hooks/*.sh`, path-restriction hook, README "When CC #14200 Lands" | **Watch** | cdocs' hooks are bash matching on tool-call shape (`validate-cdocs-edit-path.sh`). An `agent.spawn` hook could scope a subagent's file access at spawn time instead of after the fact - closer to "file ownership by construction." Not urgent; current hooks work and a rewrite buys robustness, not new capability.
| **Anthropic Code Review** (multi-agent PR review product) | `review` skill, `reviewer`/`judge` agents, "fresh reviewer every iteration" | **Note: cdocs already does the variant that matters** | cdocs' fresh-reviewer-per-round pattern is the same shape, applied to proposals/devlogs/code diffs uniformly, for free (a dispatched subagent, not a $15-25 metered product), and already composed with a judge for loop meta-health, which the vendor tool lacks. Could lean on it later for deep code-diff review a cdocs reviewer can't reach cheaply, but it duplicates cdocs' own mechanism rather than adding one.
| **Spec Kit / Kiro** (spec→plan→tasks→implement) | `propose`, `propose-revise`, `implement` | **Note: cdocs already does the thing** | Structurally identical to proposal-with-phases → `implement`/`iterate`. `/speckit.converge` (closing the spec-vs-code loop) is the same problem cdocs solved days before this report (`646fe38 fix(triage): disambiguate proposal-accept from implementation-accept rows`). No new idea to take; useful confirmation the problem class is industry-wide, not cdocs-specific overengineering.
| **Dreaming** + **Letta's move to git-backed memory files** (memory-store consolidation) | `/cdocs:triage`, devlog Scratchpoint/handoff | **Ignore / soft validation** | Dreaming consolidates an opaque memory store; triage consolidates git-diffable markdown frontmatter and state, which is strictly more auditable (every consolidation is a commit, not a black-box rewrite) - validates the *need*, not the *mechanism*. Letta (a dedicated memory-agent company) independently converging on git-backed files as its durable-state substrate is a second data point for cdocs' founding bet. No action needed either way.
| **Agent teams / "teammates," `/advisor` pairing** | Durable-specialist pattern in `orchestration-discipline.md` | **Watch** | Platform-native resumable/idle-stateful agents and cross-model advisory pairing converge on patterns cdocs already encodes by convention (`SendMessage`-resumed specialist, `-f/--first-round`, model-tiering's opus-for-judgment). If "teammates" stabilizes as a first-class object, the durable-specialist clause could point at it directly - not there yet (still bugfix-level changelog entries, not a settled primitive).
| **Evaluation literature** (Scaffold Effect, benchmark-misalignment position paper, SWE-bench Pro data-quality audit) | `--verification-floor` requirement in `iterate`, `model-tiering.md` | **Watch (informational)** | External validation, not a mechanism to adopt: the Scaffold Effect thesis (harness choice is a hidden variable in measured agent capability) is the premise cdocs is built on, and the benchmark-misalignment critique backs trusting a concrete, per-task verification floor with a failure picture over a generic numeric score. No rule change implied; a citation worth keeping if the maintainer is ever told cdocs' process overhead "doesn't show up in the benchmarks."
| **Cognition's "Multi-Agents: What's Actually Working"** and Anthropic's own "when to use multi-agent systems" post | `orchestration-discipline.md` ("one writer per file"), `agents/judge.md` | **Validated, no change needed** | Two competing vendors independently published the exact two rules cdocs' orchestration discipline already states: keep writes single-threaded per file, and give a verification agent an explicit, checkable completion criterion rather than trusting its own "done" (the "early victory problem" `judge` exists partly to catch via reviewer-escalation, not self-report). Strongest evidence in this report that cdocs' core discipline is right, not over-engineered; nothing to add.
| **GitHub Copilot's `.github/agents/`** (checked-in, repo-local agent process config) | `plugins/cdocs/skills/*`, README "Installation" | **Watch, borrow idea** | The clearest case of a vendor absorbing a slice of what a process plugin provides natively: a team codifies a repo-specific agent step with no plugin install. It does not threaten cdocs' broader document lifecycle (proposals/devlogs/reviews/reports), only the "how do skills get into a repo" delivery question already tracked in README "Rules Integration" pending [CC #14200](https://github.com/anthropics/claude-code/issues/14200). Worth a glance if that issue lands with a similar checked-in convention cdocs could mirror instead of inventing its own.

## What's missing / could not verify

No primary-source confirmation was found for: Factory.ai's valuation/scale claims, Kiro's exact GA date (May 7, 2026, corroborated only by secondary roundups, no AWS first-party post found), Amp's subagent architecture, and the "Claude Mythos Preview 16-hour METR horizon" figure (a single social-media post, not METR's own blog). Treat these as directionally correct but not load-bearing.
No evidence surfaced of a competing *document-driven* process plugin (proposals/devlogs/reviews/reports as a cohesive, git-committed lifecycle) from any vendor; the overlap found is all at the orchestration-primitive layer (Workflow tool) or the point-solution layer (Code Review, Spec Kit), not the "whole development process as documents" layer cdocs occupies.
