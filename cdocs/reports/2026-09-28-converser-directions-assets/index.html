Converser Directions

BLUF

Start with host voicemode serve, one process and token per container, against an unmodified weftwise container. It is config only (1.5–3 person-days) and it takes the pulse socket, monitor-source capture, inode pinning and the in-container audio install out of the container. Because every host serve process shares the hardcoded conch, it also closes cross-container talk-over. Run it for a week and package a lace feature only if voice gets used. Keep the amended in-container proposal as the fallback. Use the tier-2 question redirect in v0, since the 12 s tier-3 relay cannot beat a ~15 s voice round trip. A VoiceMode fork or an owned broker waits for a named tripwire, and Android starts with Remote Control plus phone dictation while VoiceMode Connect's Android client matures upstream.

Ground truth

Facts the reviews settled

These corrections from the review rounds change which options differ from each other. Everything below builds on them.

  • No differentiator in label=disable. The devcontainer CLI 0.87.0 applies it to every podman container, together with --userns=keep-id. No design gains or loses SELinux confinement.
  • The token is the only gate. pasta -T traffic arrives as 127.0.0.1, so serve's allowlist admits everything. That means one serve process and one token per container.
  • Default serve is too wide. It exposes converse and service (host systemd control), and STT falls back to OpenAI. Set VOICEMODE_TOOLS_ENABLED=converse and loopback-only STT/TTS URLs.
  • Host conch is shared automatically. The path is hardcoded to ~/.voicemode/conch, so all same-user host serve processes serialize. A per-project VOICEMODE_BASE_DIR isolates transcripts and logs.
  • Concurrency bugs are open. #521 (shared-process guard) and #522 (reconnect mid-listen) have no maintainer response. PR #523 addresses #522's stream-death symptom and is not a concurrency fix.
  • First experiment is host serve. The container stays unmodified apart from one pasta -T line. The in-container stack is the fallback.
  • Separate OS user: feasible, rejected for v0. An own-child poster relay makes it work. The cost is two poster kinds, a second login and a new send tool.
  • Tier 3 deferred. The 12 s relay timeout is infeasible against a ~15 s optimistic floor, plus up to 120 s waiting behind an open listen. v0 uses tier 2.
  • Stop-hook volume is up to 50–150 wakes/h. That is a coincident-peak upper bound for five overseers (24–30 turns/h peak, 8–16 typical). Every wake is a Sonnet turn on the same subscription.
Architecture

Baseline against the host-serve split

The whole difference is where the microphone lives. In the baseline the container holds a raw pulse socket. In the split it holds an HTTP URL and a bearer token.

Message flow

A spoken request, the reply, and a redirected question

The converser is woken twice per exchange: once by the user's voice, once by the overseer's Stop post. The v0 question path denies AskUserQuestion and asks the overseer to route the question through the converser. No relay hook waits on a timeout.

Host serve configuration and the smallest experiment required env, success criteria

Run on the host, one per container:

  • voicemode serve --host 127.0.0.1 --port 8765 --token <random>. Never bind 0.0.0.0: with only LOCAL_CIDRS active, the banner omits its security section and every RFC1918 peer gets the full tool surface.
  • VOICEMODE_TOOLS_ENABLED=converse. The unset default is converse,service, and service starts and stops host systemd --user units.
  • VOICEMODE_STT_BASE_URLS and VOICEMODE_TTS_BASE_URLS pinned to loopback. The default list ends in api.openai.com, so stopping whisper would fail audio over to the cloud.
  • A per-project VOICEMODE_BASE_DIR for transcripts, audio and logs. The conch stays shared. Only a per-process HOME override would split it, which reopens double capture.
  • Keep listen_duration_max short and the client tool timeout above the server's longest converse(), so the client never abandons a live call (the #522 trigger).

Pre-check in a throwaway container, no real devcontainer.json touched: podman run --rm --network pasta:-T,8765 …, then claude mcp add --transport http with a bearer header, or voicemode mcp-bridge. Pass criteria:

  • a raw tools/list with no token returns 401;
  • with the token it lists only converse;
  • one converse() completes end to end;
  • two containers with their own serve processes serialize on the shared conch.

Then the real first experiment: one --network pasta:-T,8765 line in weftwise's runArgs and an HTTP MCP entry for the converser.

What the pulse socket costs under the in-container fallback verified live in jif
  • Monitor sources. pactl list short sources in jif lists every sink's .monitor, so any container process can record system output as well as the mic.
  • Module loading. A pulse client can plausibly reconfigure the host audio server. This was not tested because the test would mutate host state.
  • Inode pinning. A file bind breaks with ConnectionRefusedError after the socket is recreated, while a directory bind survives. Amendment 4: mount /run/user/1000/pulse as a directory. A logout with Linger=no breaks both styles.
  • Double capture. Per-project conch directories mean two hands-free conversers transcribe one utterance and both act. Bind-mounting one conch directory into several containers is untested, and its psutil.pid_exists stale-reclaim cannot see PIDs in another container's namespace.
  • jif audio works today. pactl info returns protocol 35, which corrects the proposal's "plausibly non-functional" claim.

Why the allowlist cannot help, and what the token has to carry serve_middleware.py

pasta opens the host-side connection itself, so every forwarded peer appears as 127.0.0.1. serve's default allowlist (127.0.0.0/8, ::1, all of RFC1918) therefore cannot tell one container from another or from a host process. The token check is the only discriminator:

  • It is a plain != comparison, not constant-time. That is negligible over loopback.
  • Whether FastMCP validates Host/Origin is unverified, which leaves a possible DNS-rebinding exposure without a token.
  • --strict-mcp-config constrains only the converser's own client. Any container process can POST raw JSON-RPC at the port, so tool scoping has to happen host-side.
  • Whether pasta forwards gRPC's HTTP/2 framing is untested. Only HTTP/1.1 has been verified.
Decision

Converser isolation

A bypass overseer holds every inbound message except one from a bypass sender, so over native messaging the converser is forced into bypass mode. Tool surface bounds what the converser can do directly. Relayed injection is untouched by every option here; only spoken confirmation and push-to-talk address it.

Separate OS user: the full feasibility finding vetting §2b
  • Native messaging across UIDs is blocked over the local socket. Claude Code restricts the socket to its OS user and refuses socket directories another user owns. All sockets are srw------- node.
  • The relay that makes it work. A session delivers a message verified as coming from its own child. claude is not PID 1 in lace containers, so process evidence exists. Each overseer's SessionStart hook spawns a poster that reads a shared inbox directory and posts to its parent's socket. A mirror poster under uid 1001 does the same for the converser.
  • Open question. A SessionStart-spawned poster outlives its hook and is reparented to PID 1. The docs cover children that exited, not reparented ones. The second arm of gate (n) is the CLAUDE_CODE_MESSAGING_TOKEN auth line.
  • Side effect. Anything that can write an inbox directory is delivered as own-child, even to bypass overseers.
  • Credentials. Copying .credentials.json shares a rotating refresh token and may break one holder (unverified). Hence the second login.
  • Why the case shrinks under host serve. VoiceMode's code runs on the host, so the in-container converser is only claude plus an HTTP MCP client.
Launcher details that bound the tool surface proposal r4, amendment 7
  • --tools restricts built-in tools only. The MCP surface is bounded by --mcp-config + --strict-mcp-config + VOICEMODE_TOOLS_ENABLED=converse.
  • ENABLE_TOOL_SEARCH=false loads MCP tools upfront, since a restrictive --tools may drop ToolSearch.
  • Add --disallowedTools "mcp__claude_ai_*" by default. Nobody has verified whether strict MCP hides claude.ai connector tools, and in bypass mode they would run unprompted.
  • Use a single-instance flock in the launcher. The sockpath file is last-writer-wins.
  • crossSessionInbound: "accept" goes only in the converser's --settings, never container-wide. CONVERSER_SESSION=1 excludes the converser from its own Stop hook.

Hard-won subsystems worth reusing: VAD endpointing, health-checked provider failover, the FIFO flock conch (676 + 696 + 446 lines), TTS streaming, and the HTTP/SSE transport with middleware.

Tripwires that justify moving from (a) toward (c) or (d)
  • Concurrency: needing more than one client per serve process, or being unable to keep the client timeout above the longest converse(). Propose an in-process asyncio.Lock upstream first.
  • Non-blocking listen: if it proves necessary, propose it upstream and fork only after a 30-day stall.
  • Upstream remote features land and do not fit: re-evaluate once VM-970 and Ambient Voice ship. If they solve Android outright, (d) is unlikely to ever pay off.
  • Bus-factor risk materializes: the release gap recurs, or #521-class issues stay unaddressed past the SLA. That is the strongest case for a minimal independent patch set.

How host serve extends to a phone, and where it breaks #521 applies here

Host serve is the seam every remote path plugs into. The one-client-per-process discipline that keeps #521 closed breaks as soon as a phone client and a container converser share one serve process. Two options at that point:

  • a separate serve process for the phone, which serializes against the container's through the shared conch;
  • the in-process lock, landed upstream or carried as a patch.

Wyoming carries no authentication or encryption by design, so it can sit behind the broker but never across the container boundary. Rhasspy is superseded, and wyoming-satellite is unmaintained.

Trust

Threat map

The converser holds two kinds of authority that its inputs lack. It speaks for the user, and it carries the bypass class that passes overseer holds.

Other threats from the proposal's table that still apply both placements
  • Turn-end content exposure. Secrets in last_assistant_message may be spoken aloud and logged. v0 has no content filter.
  • Transcript retention. Ambient speech becomes Claude prompts stored in the shared ~/.claude/projects. VoiceMode logs persist per project.
  • Reply-file forgery (tier 3 only). Any same-UID process could answer a question on the overseer's behalf.
  • Cloud fallback. Voice content leaves the host if a provider key and the default URL list come back.
  • Silent managed-source override. Server-managed settings replace the container's drop-in without a warning. /status checks for this.
