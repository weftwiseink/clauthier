## Fixtures (session scratchpad, outside the repo)

The fixtures were regenerated by a seeded Python generator, using the same shapes as [`2026-10-05-bash-runner-quality-canary.md`](2026-10-05-bash-runner-quality-canary.md).
Ground truth (file, `it` line, assertion line, name, actual, expected) is written by the generator from the fixture sources, not parsed from the output.

- **A (17 failures):** `node --test --test-reporter=spec "tests/*.test.mjs"`, 6 files, 360 tests, 17 distinct `deepStrictEqual` failures, 34,058 chars, 844 lines, exit 1.
- **E (45 failures):** same shape, 9 files, 450 tests, 68,525 chars, 1,704 lines, exit 1.
- **P (all pass):** same shape, 6 files, 360 tests, 15,857 chars, 380 lines, exit 0.
- **B (sweep):** `grep -rn legacyFetch src` over 30 files: 255 lines (34,706 chars). 49 are real `legacyFetch(` call sites in 24 files. The other 206 lines are 30 imports and 176 `// was legacyFetch before migration` comment decoys.

## Method

`claude -p --plugin-dir <abs>/plugins/cdocs --model sonnet --output-format stream-json --verbose --dangerously-skip-permissions '<prompt>'`, run from the fixture dir.
The prompt tells the parent to dispatch `cdocs:bash-runner` with the stated spec, or with only the command for no-spec runs.
It tells the parent not to run the command itself, and to relay the report verbatim.
Every parent dispatched exactly once and ran no Bash of its own.
Runner model `claude-sonnet-5-5`, Claude Code `2.1.289`, plugin at `HEAD` `6c2a2fe`.
The report is taken from the runner's final message (the parent dispatched in the background).
A Python checker matches each ground-truth row to a report line on name, then on location (the `it` or assertion line), actual and expected.

## Observations

- **Spec'd completeness holds without contract bending.** Every spec'd list was built by one command (`awk`, or `grep \| cut`) and pasted into `Excerpt:`. The r1 canary's composed lines, over-cap reports and `c 28 197 190` shorthand are gone.
- **No overcorrection.** When the spec asked only for pass/fail, or the run passed, reports stayed under 1K. O1 named the list's location in `see:` rather than including it.
- **The no-spec default is count-sensitive.** At 17 failures it lists them; at 45 it usually falls back to totals. The no-spec bullet asks for each failure, but the 12K allowance is keyed only to a spec that says "every". With 45 lines over the ~4K default, 2 of 3 runs dropped the list.
- **Residual runner slips, all disclosed:** A2 fixed a wrong command's output in `Summary:` instead of re-running the fixed command. B1 and A2 miscounted files in `Summary:`. N2 put an invented claim in `Truncated:`.
- **Capture location is fixture-induced.** Under `claude -p` the runner's environment lists no scratchpad. Because the fixture dir sat under this session's scratchpad, 17 of 18 runs wrote their capture into the fixture dir, which is a path containing "scratchpad". B1 wrote into this session's scratchpad itself, the dir above the fixture. No capture landed in the repo.
